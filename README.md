# لعبة المسابقات الجماعية

موقع ثابت (HTML/CSS/JS بدون فريمورك أو build tools) للعبة مسابقات جماعية بنظام هوست،
يتزامن فوريًا بين جوال الهوست وشاشة العرض عبر Firebase Realtime Database.

## هيكل الملفات

- `index.html` — صفحة اختيار: لوحة التحكم أو شاشة العرض
- `host.html` + `js/host.js` — لوحة تحكم الهوست (خاصة بجوال مدير اللعبة)
- `display.html` + `js/display.js` — شاشة العرض (تُعرض على التلفزيون)
- `admin.html` + `js/admin.js` — إدارة الأسئلة (إضافة/حذف)
- `js/sample-data.js` — سؤالان جاهزان للاستيراد التجريبي
- `js/firebase-init.js` — تهيئة Firebase وشارة حالة الاتصال
- `firebase-config.js` — إعداداتك الخاصة بـ Firebase (تعبّئها بنفسك)
- `style.css` — التصميم المشترك بين كل الصفحات

## 1) تجهيز Firebase Realtime Database

1. افتح [Firebase Console](https://console.firebase.google.com) وأنشئ مشروعًا جديدًا (أو استخدم مشروعًا موجودًا).
2. من القائمة الجانبية: **Build → Realtime Database → Create Database**.
   - اختر موقع الخادم المناسب.
   - ابدأ بوضع **Test mode** (قواعد مفتوحة للقراءة/الكتابة) لتجربة سريعة. هذا يكفي لعبة داخل مكان واحد، لكن تذكر أن أي شخص يعرف رابط قاعدة البيانات يقدر يعدّل عليها. إذا تبي تشدّد الحماية لاحقًا، عدّل قواعد Realtime Database من تبويب **Rules** إلى شيء مثل:
     ```json
     {
       "rules": {
         ".read": true,
         ".write": true
       }
     }
     ```
     (هذا هو الافتراضي في Test mode، وهو كافٍ لهذا الاستخدام لأن اللاعبين لا يفتحون الموقع أصلًا.)
3. من **Project settings → General → Your apps**، أضف تطبيق ويب (Web app) واحصل على كائن `firebaseConfig`.
4. افتح ملف `firebase-config.js` في مجلد المشروع وعبّي القيم:
   ```js
   const firebaseConfig = {
     apiKey: "...",
     authDomain: "...",
     databaseURL: "...",
     projectId: "...",
     storageBucket: "...",
     messagingSenderId: "...",
     appId: "...",
   };
   ```
   أهم حقل هو `databaseURL` (يشبه `https://your-project-id-default-rtdb.firebaseio.com`) — بدونه ما راح يشتغل التزامن.

## 2) التجربة محليًا

افتح `index.html` مباشرة بالمتصفح (أو استخدم أي خادم ثابت بسيط مثل امتداد Live Server في VS Code). لا حاجة لأي تثبيت أو npm.

- افتح `admin.html` وسجّل دخول بكلمة السر الافتراضية: **`admin1234`**
  (يمكنك تغييرها بتعديل المتغير `ADMIN_PASSWORD` في أعلى ملف `js/admin.js`.)
- افتح `host.html` وسجّل دخول بكلمة السر الافتراضية: **`host1234`**
  (يمكنك تغييرها بتعديل المتغير `HOST_PASSWORD` في أعلى ملف `js/host.js`.)
  كلا الحمايتين حماية واجهة بسيطة فقط (client-side)، وليست حماية أمنية حقيقية — أي شخص يفتح الكود المصدري يقدر يشوفها. `index.html` و `display.html` تبقيان بدون كلمة سر.
- من `admin.html` اضغط "استيراد أسئلة تجريبية" لإضافة سؤالين جاهزين فورًا.
- من `host.html` اختر أحد السؤالين.
- افتح `display.html` من جهاز/تبويب آخر وشاهد التحديث الفوري عند ضغط الإجابات من الهوست.

## 3) ترتيب الأسئلة و"السؤال التالي"

زر "السؤال التالي" في لوحة الهوست يتنقل ضمن ترتيب الأسئلة كما تظهر مجمّعة حسب التصنيف في `admin.html`
(بترتيب إضافتها). لا حاجة لترتيب يدوي إضافي — فقط أضف أسئلتك بالترتيب الذي تريد لعبها به داخل كل تصنيف.

## 3.5) نظام نقاط الفريقين

اللعبة الآن بين فريقين، وبأي لحظة السؤال "عند" فريق معيّن (`game/turnTeam`). في لوحة الهوست:

- **الضغط على أي إجابة بالقائمة** = إجابة صحيحة: تُكشف الإجابة (باتجاه واحد، ما ترجع تتغطى)، نقاطها تُضاف تلقائيًا لصاحب الدور الحالي، وينتقل الدور فورًا للفريق الثاني.
- **زر "إجابة خطأ (تبديل الدور)"** = ينقل الدور للفريق الثاني بدون ما يكشف أي إجابة أو يعطي نقاط.
- **الضغط على بطاقة أي فريق** = تحكم يدوي احتياطي لتحويل الدور لذاك الفريق مباشرة.
- **أيقونة ✎ بجانب اسم الفريق** = تفتح نافذة صغيرة لإعادة تسمية الفريق (مفيدة لوضع أسماء أشخاص حقيقية).
- **زر "بدء لعبة جديدة"** = يصفّر نقاط الفريقين ويرجّع الدور للفريق الأول (بعد تأكيد، لأنه يمسح النقاط).
- أزرار "إظهار كل الإجابات"، "إعادة تعيين الجولة"، "السؤال التالي" لا تغيّر النقاط ولا الدور — النقاط والدور يبقيان محفوظين عبر كل أسئلة نفس اللعبة، وينصفّرون فقط بزر "بدء لعبة جديدة".

نفس شريط الفريقين (بدون تحكم، للعرض فقط) يظهر أعلى `display.html` ويتحدث فوريًا.

## 4) النشر (Netlify - الخيار الافتراضي)

1. افتح [app.netlify.com/drop](https://app.netlify.com/drop)
2. اسحب مجلد المشروع كامل (بما فيه `firebase-config.js` بعد تعبئته) وأفلته في الصفحة
3. Netlify يعطيك رابطًا فوريًا — افتحه من جوال الهوست وجوال/شاشة العرض

أي استضافة ثابتة أخرى تعمل بنفس الطريقة (GitHub Pages، Vercel، Firebase Hosting نفسه، إلخ) لأن الملفات خام بدون أي build step.

## 5) ملاحظات أمان

- كلمتا سر `admin.html` و `host.html` حماية واجهة فقط (client-side) لمنع الدخول العرضي، وليست حماية حقيقية ضد شخص يقرأ كود الصفحة.
- قواعد Realtime Database في وضع "Test mode" مفتوحة بالكامل. هذا مقبول للعبة تُلعب في مكان واحد ولا يفتح الموقع فيها أحد غير الهوست وشاشة العرض، لكن لا تشارك رابط `databaseURL` أو الموقع المنشور علنًا إذا ما تبي أي شخص يقدر يعدّل البيانات.
